## Fixed locally

1. Opening the mobile menu and widening the viewport to desktop left body scrolling locked. `components/Navbar.tsx` now closes the menu at the desktop breakpoint, allowing the existing effect cleanup to restore scrolling. Added a regression assertion to `test/browser.cjs`.
2. Removed unused `serve` and applied compatible dependency updates using `npm audit fix`. The installed Next.js version is now 16.4.2 and Sharp is 0.35.5. The production-only dependency audit reports zero vulnerabilities.
3. Expanded the browser test harness with WebKit selection, a configurable isolated test port and HTTP request guard checks. The route crawl now waits for network idle before navigating onward.

The first WebKit run completed the user journeys but failed its zero-page-errors assertion with access-control errors during rapid navigation. Waiting for network idle before leaving each crawl page eliminated those errors; the complete repeat passed without suppressing or filtering errors. This was a test synchronization issue in the observed runs.

The published site still contains the menu resize bug until these changes are deployed. The current local `out` directory is a default API-backed build, not the WhatsApp review build: publishing this artifact directly to static Firebase hosting would break the inquiry submission flow. A review deployment must be rebuilt with `NEXT_PUBLIC_INQUIRY_MODE=whatsapp` first.

## Remaining findings and limits

- **Development dependency advisories:** `braces` and `postcss-selector-parser`, plus their dependent packages in Tailwind 3's tree, remain flagged. npm's suggested resolution involves a breaking Tailwind 4 upgrade. This migration was not included in the QA fixes. A zero production audit does not mean the whole development dependency tree is clear.
- **SEO:** `/villas` inherits the homepage title, so these two pages have the same document title. All tested pages have descriptions, but canonical link elements were absent in the crawl. Add route-specific Stays metadata and canonical URLs as SEO follow-up work.
- **Known product scope:** no live booking/availability or payment provider is connected. Spanish is an introductory page, not a full translation. These are visible product limitations, not successful end-to-end integrations.
- External social destinations, actual message delivery, payment processing, real iPhone/Android hardware and load/stress testing were not exercised. No Core Web Vitals claim is made from these functional tests.
